# 요구사항 정의서 — Message Bottle (유리병 편지)

## 1. 사용자와 문제

| 항목 | 내용 |
|---|---|
| 사용자 | 로그인한 일반 사용자 (편지를 보내고 받는 사람. 권한이 다른 사용자 종류는 없다) |
| 이용 상황 | 스마트폰 앱에서, 다른 사람의 바다로 편지 한 통을 보내거나 내 바다에 도착한 편지를 열어 볼 때 |
| 해결할 문제 | 채팅처럼 대화방과 즉각적인 응답에 얽매이지 않고, 편지 한 통 단위로 보내고 받는 소통이 필요하다. 서비스 정의: 실시간 채팅이 아니다 |
| 핵심 자료 | 편지(유리병). 한 통이 하나의 독립된 자료이며, 답장도 기존 대화에 붙지 않고 새 편지가 된다 |
| 기대 결과 | 상대방의 바다로 편지를 보내고, 내 바다에 도착한 편지를 읽은 뒤 보관하거나 버릴 수 있다 |

## 2. 범위

기본 범위: 로그인 후 내 바다 조회(떠 있는 편지 최대 10개, 초과분은 대기), 편지 쓰기·발송(익명 선택 포함), 편지 열람, 보관, X 버튼을 통한 영구 삭제, 답장(바다에서 받은 직후에만, 임시 저장 포함), 보낸 편지함·받은 편지함 조회, 받은 편지함에서 삭제, 발송 후 7일 만료, 내 바다 공개/비공개 설정, 다른 사람의 공개 바다 방문(아이디와 유리병 개수만, 받은 편지의 보낸 사람을 눌러 진입).

선택 확장: 편지 연결(스레드) 조회, 별도 프로필 화면(내 정보 조회), 공개 바다 방문자가 편지를 열어 보는 기능(Q17, 나중에 결정). 바다 공개 설정은 프로필 화면 없이 내 바다 화면의 설정 창에서 바로 한다.

공통 화면: S00 로그인은 제공 화면을 연결한다. 별도 회원 가입·비밀번호 찾기는 이 장의 기본 범위에 추가하지 않는다. (프로젝트에는 가입 화면이 구현되어 있으나 이 문서의 설계 범위에는 포함하지 않는다.)

## 3. 요구사항

ID는 문서 간 연결에 사용하므로 작성 후 유지한다. 템플릿의 R03(본인 수정)은 편지를 수정할 수 없으므로 "보관"으로 대체했다.

| ID | 기능 | 시작 조건·입력 | 동작·결과 | 예외·상태 | 연결 화면 | 검증 기준 |
|---|---|---|---|---|---|---|
| R01 | 목록 조회: 내 바다의 떠 있는 유리병, 보낸 편지함, 받은 편지함. 편지 자체의 검색·필터 기능은 없다 (받는 사람 검색은 R02) | 로그인 상태에서 S01 진입. 편지함은 S01 우상단 버튼으로 연다 | 바다에는 떠 있는 편지(FLOATING)가 유리병으로 최대 10개 표시된다. 보낸/받은 편지함은 팝업 목록으로 표시하며 길면 스크롤한다. 항목을 선택하면 S05에서 내용을 연다. 받은 편지함 카드에는 답장한 편지에만 맨 오른쪽에 체크 아이콘이 표시된다 | 편지 없음(빈 상태 안내), 읽기 실패(재시도), 이미 사라진 편지(목록 갱신) | S01, S03, S04, S05 | AC01, AC02, AC03 |

| R06 | 답장·임시 저장 | 바다에서 연 일반 편지(수신자 본인)의 하단 [답장]. 익명 편지, 받은 편지함의 편지, 보낸 편지함의 편지에는 답장할 수 없다 | 답장 화면에서 내용을 쓰고 [답장 보내기]. 돌아가기를 누르면 쓰던 내용이 임시 저장되고 원본 편지로 돌아가 내용을 다시 볼 수 있다. 다시 [답장]을 누르면 임시 저장한 답장을 불러올지 묻고, 확인은 불러오기, 취소는 새로 쓰기다. 발송하면 원 발신자의 바다로 새 편지가 가고, 원본은 자동으로 받은 편지함에 보관되며 그 카드 맨 오른쪽에 체크 아이콘이 표시된다 | 내용 비어 있음(오류), 발송 실패(입력과 임시 저장 유지), 이미 사라진 편지(안내 후 바다 갱신), 처리 중(중복 제출 방지) | S05, S06, S04 | AC16, AC17, AC18 |
| R07 | 바다 공개 설정·공개 바다 방문 | 내 바다 화면 좌상단의 바다 공개 칩으로 설정 창을 연다. 방문은 받은 편지(받은 편지함의 카드 또는 열어 본 편지)의 보낸 사람 이름을 눌러 시작한다 | 설정 창에서 공개/비공개를 바꾼다(기본 비공개). 공개된 바다를 방문하면 "OOO의 바다"라는 제목과 떠 있는 유리병 개수만 보인다. 방문자는 유리병을 눌러 편지를 열 수 없다. 비공개 바다는 서버가 접근을 막고 안내만 보여준다. 자기 바다는 비공개여도 볼 수 있다 | 설정 실패(설정은 그대로, 안내와 재시도), 비공개 바다(개수 없이 안내), 없는 사용자(안내), 읽기 실패(재시도). 익명 편지는 보낸 사람을 알 수 없어 방문 진입이 없다. 바다에서 연 편지는 처리하기 전에 다른 화면으로 가지 않는다 | S01, S07, S08, S04, S05 | AC20, AC21, AC22, AC23 |

## 4. 필드의 의미와 입력 조건

논리 이름은 문서와 화면을 연결하기 위한 이름이다. DB 자료형·테이블·API 계약은 다음 장에서 정한다.

| 논리 이름 | 화면 이름·의미 | 사용자 입력 여부 | 필수 여부 | 허용 값·길이·날짜 조건 |
|---|---|---|---|---|
| id | 자료 식별자(편지 하나) | 시스템 관리 | 필수 | 화면에 노출하지 않는 편지 고유 식별 |

| content | 편지 내용 | 입력 | 필수 | 빈 내용 불가. 길이 제한 없음(Q1) |

| senderId | 발신자 식별자(템플릿의 ownerId에 해당) | 시스템 관리 | 필수 | 로그인한 사용자와 연결. 익명 편지라도 수신자에게는 보이지 않는다 |

## 5. 공통 정책

- 검색: 편지를 검색하거나 필터링하는 기능은 없다. 받는 사람은 편지 쓰기에서 아이디로 검색해 결과 목록에서 선택한다(Q10). 검색어는 부분 일치로 찾고 대소문자를 구분한다(Q11). 글자를 칠 때마다 검색하지 않고, 입력을 멈춘 뒤 1초 동안 변화가 없을 때 한 번 검색한다. 검색어를 지우면 결과도 지우고, 검색 중에 입력이 바뀌면 이전 결과는 버린다. 검색 결과가 없으면 "일치하는 사용자가 없습니다"를 보여주고 발송하지 않는다. 검색 결과에는 아이디만 표시한다.
- 순서: 바다의 유리병은 목록 순서가 아니라 겹치지 않게 배치한다. 대기 편지는 먼저 발송된 것부터 바다에 올린다. 보낸/받은 편지함은 최근 것이 위에 오는 순서로 보여준다(Q4).
- 취소: 편지 쓰기에서 입력한 내용이 없으면 바로 닫고, 입력한 내용이 있으면 폐기 확인을 거친다. 바다에서 연 편지는 X(영구 삭제 확인) 외의 방법으로 닫거나 삭제하지 않는다. 바깥 배경 터치로는 편지 상세를 닫지 않는다.
- 뒤로 가기: Android 뒤로 가기 버튼·제스처는 앱 안의 뒤로 가기 버튼과 똑같이 동작한다(Q9). 앱 안에 뒤로 가기 버튼이 없는 화면(바다에서 연 편지 상세)에서는 아무 일도 하지 않으며 편지를 닫거나 삭제하지 않는다. 답장 화면에서는 돌아가기와 같아서 쓰던 내용을 임시 저장하고 원본 편지로 돌아간다.
- 임시 저장: 답장 화면에서 돌아가면 내용이 있을 때만 임시 저장하고, 비어 있으면 저장하지 않는다. 임시 저장한 답장은 원본 편지를 다시 열어 [답장]을 누를 때 불러올지 묻는다. 그 편지에 답장을 보내거나 그 편지를 보관·버리면 임시 저장도 지운다.
- 열람 후 이탈(2026-11-10 변경): 편지를 한 번 열었으면 답장하거나 보관하거나 X로 버려야 한다. 이 셋 없이 앱 종료 등으로 그 편지를 더 이상 볼 수 없게 되면 버린 것으로 처리한다. 영구 삭제이며 받은 편지함에 저장되지 않고 바다에 다시 나타나지 않는다. 발신자의 보낸 편지함 기록은 유지된다. 임시 저장한 답장도 함께 지운다. 앱이 종료된 뒤 다시 시작해 바다를 불러올 때 판단하며, 종료 전에 답장·보관·버리기를 하는 것은 사용자의 책임이다(Q15). 서버가 처리했다고 확인해 주기 전에 앱이 종료되어도 구제하지 않으므로 확인 안내가 나올 때까지 기다려야 한다(Q16). 프로젝트 명세(CLAUDE.md)도 이 규칙으로 바꾸었다.
- 실패: 발송·보관·삭제가 실패하면 입력과 화면 상태를 유지하고 안내와 재시도를 제공한다. 서버에서 확인되지 않은 성공을 화면에 표시하지 않는다.
- 권한: 로그인하지 않으면 S00으로 보낸다. 보관과 삭제는 수신자만 할 수 있고, 발신자는 보낸 편지를 읽기만 한다. 편지 접근 권한은 서버에서도 검증한다.
- 개인정보: 이메일 등 아이디·비밀번호 외 개인정보를 수집하지 않는다. 비밀번호는 평문으로 저장하지 않는다. 익명 편지의 발신자 정보는 수신자에게 어떤 화면·응답으로도 보이지 않는다.
- 공개 바다: 방문자에게는 누구의 바다인지(아이디)와 현재 떠 있는 유리병 개수만 보여준다. 편지 id·내용·발신자·발송 시각·대기 편지는 어떤 응답에도 없다. 대기 중이거나 만료·보관·버려진 편지는 개수에 넣지 않는다. 비공개 바다는 주인 외에는 서버가 막는다. 방문은 읽기만 하며 주인의 편지 상태(열람 후 이탈 정리 등)를 바꾸지 않는다.
