# 포트폴리오_MessageBottle speaker notes 
## 1. Message Bottle

Message Bottle을 소개하겠습니다. 다른 사람의 바다로 유리병 편지를 보내고, 내 바다에 도착한 편지를 읽는 앱입니다. 오른쪽 화면은 시안이 아니라 Android 에뮬레이터에서 실제로 실행한 내 바다 화면이고, 유리병 하나가 편지 한 통입니다. 이 자료는 2026년 11월 11일에 만든 발표본이며, 최종본은 발표 뒤에 고친 내용을 반영해 따로 저장할 예정입니다.

## 2. 앱 소개

이 앱은 실시간 채팅이 아닙니다. 대화방과 바로 답해야 하는 부담 없이 편지 한 통 단위로 주고받는 것이 목적입니다. 사용자는 로그인한 일반 사용자이고, 편지 한 통을 보내거나 내 바다에 도착한 편지를 열어 볼 때 씁니다. 사용자는 유리병을 보내고, 열어 보고, 답장·보관·버리기 중 하나를 고릅니다. 이 내용은 요구사항 정의서 1장에서 옮겼습니다.

## 3. 사용자와 문제

기능을 정한 이유를 사용자의 상황과 연결한 표입니다. 부담 없이 소식을 전하고 싶다는 상황에는 아이디로 받는 사람을 검색해 편지를 보내는 기능과 익명 선택을, 읽고 나서 남길지 정하고 싶다는 상황에는 답장·보관·버리기를 연결했습니다. 보낸 편지는 보낸 편지함에 계속 남고, 편지가 몰려도 바다에는 최대 10개만 보이고 나머지는 순서대로 기다립니다. 모두 요구사항 문서에 적은 내용이며, 통계나 만족도 같은 수치는 조사한 적이 없어 넣지 않았습니다.

## 4. 주요 기능

핵심 기능 여섯 가지와 각각을 어디까지 확인했는지입니다. 가입과 로그인, 편지 보내기, 열람 후 보관과 버리기, 사용자별 화면 설정은 에뮬레이터에서 직접 눌러 보고 API 응답과 DB 값까지 확인했습니다. 익명 편지는 에뮬레이터에서 보관 버튼만 나오는 것을 확인했습니다. 답장, 공유 바다, 다른 사람의 바다 방문은 자동 테스트로만 확인했고 기기 화면으로는 보지 않았기 때문에 그렇게 적었습니다. 기기 확인은 모두 Android 에뮬레이터 기준이고 실제 휴대폰에서는 아직 실행하지 않았습니다.

## 5. 화면 흐름

대표 사용 순서입니다. 로그인하면 내 바다에서 시작합니다. 유리병을 누르면 편지 상세로, 편지 쓰기 버튼을 누르면 편지 쓰기 창으로 갑니다. 편지 쓰기에서 보내기를 누르거나, 편지 상세에서 답장·보관·버리기 중 하나를 하면 다시 내 바다로 돌아오고 결과는 보낸 편지함과 받은 편지함에 남습니다. 질문 대비: 편지 쓰기를 취소하면 입력이 있을 때만 버릴지 묻고, 보내기나 보관이 실패하면 입력과 편지를 그대로 둔 채 안내가 나옵니다. 편지 상세는 바깥을 누르거나 뒤로 가기를 해도 닫히지 않습니다.

## 6. 디자인과 실제 화면

왼쪽은 HTML로 만든 디자인 시안이고, 오른쪽은 에뮬레이터에서 실제로 실행한 앱 화면입니다. 두 화면의 종류는 아래 글로 구분해 적었습니다. 색과 글자 크기, 버튼 모서리는 디자인 기준 문서의 값을 앱의 테마 파일 한 곳에 옮겨 공통으로 씁니다. 시안과 다른 점도 있습니다. 시안에는 입력 칸 위에 라벨이 따로 있지만 앱은 입력 칸 안에 표시합니다. 또 구현 뒤에 문서와 값이 달랐던 세 가지, 편지 본문 글자 크기와 줄 간격, 확인 창 모서리, 보관 버튼 글자의 명암비는 문서 기준에 맞춰 고쳤습니다.

## 7. 전체 구조

구조는 세 부분입니다. Flutter 앱은 화면과 입력, 상태 표시를 맡고, Spring Boot 서버는 API와 JWT 인증, 편지 규칙 검증을 맡고, MySQL은 사용자와 편지, 보관, 설정을 저장합니다. 앱은 DB에 직접 접근하지 않고 서버 API만 호출하며, 편지 상태와 권한은 화면이 아니라 서버가 판단합니다. 제공된 예제는 H2를 썼지만 이 프로젝트는 MySQL 8.0으로 구성했습니다. 앱과 서버를 실제로 연결해 에뮬레이터에서 주고받는 것까지 확인했습니다.

## 8. 데이터 설계

왼쪽은 데이터 모델 문서의 테이블 관계입니다. 편지는 보낸 사람과 받는 사람으로 사용자와 연결되고, 답장은 바로 앞 편지를 부모로 가리킵니다. 보관은 편지 한 통에 한 번만 됩니다. 오른쪽은 개발 DB에서 실제로 조회한 결과입니다. 편지 22번은 보관되어 ARCHIVED이고, 23번과 24번은 버려서 DISCARDED, 26번은 상대 바다에 떠 있어 FLOATING입니다. 문서의 테이블·열 이름과 실제 DB의 이름이 같은지 대조했습니다. 화면의 계정은 확인용으로 만든 것이고 비밀번호 같은 민감한 값은 넣지 않았습니다.

## 9. API 요청과 응답

실제로 실행한 요청 하나입니다. POST /api/letters로 받는 사람과 내용, 익명 여부를 보냈고, 201 응답과 함께 편지 id 22가 발급됐습니다. Postman 대신 curl로 실행했고, 인증 토큰 값은 자료에서 뺐습니다. 명세의 예시가 아니라 실제 응답을 그대로 옮긴 것입니다. 질문 대비: 이 22번 편지는 앱에서는 받는 사람의 바다에 유리병으로 보였고, 열면 같은 내용이 나왔으며, 앞 장의 DB 조회에서도 같은 id로 확인됩니다.

## 10. 앱 기능 시연

대표 기능인 편지 보내기입니다. 시작 상태는 로그인한 내 바다입니다. 첫 화면에서 받는 사람을 검색해 고르고 내용을 입력합니다. 보내기를 누르면 두 번째 화면처럼 보냈다는 안내가 나오고, 세 번째 화면처럼 보낸 편지함에 방금 보낸 편지가 한 줄 생깁니다. 보내기를 연달아 두 번 눌러도 한 통만 갔습니다. 세 화면 모두 Android 에뮬레이터 Pixel 9에서 직접 찍은 것이고, 실제 휴대폰이나 iOS에서는 확인하지 않았습니다. 첫 화면의 둥근 단추와 말풍선은 에뮬레이터 키보드의 것입니다. 시연이 안 되면 이 화면으로 설명을 이어갑니다.

## 11. 예외와 권한 확인

정상 동작 외에 직접 실행해 본 여섯 가지입니다. 받는 사람이나 내용 없이 보내면 항목 아래에 안내가 나오고 요청을 보내지 않습니다. 토큰 없이 호출하면 401이 옵니다. 다른 사용자가 남의 편지를 보관하거나 버리려 하면 404가 오고 DB 값은 그대로였습니다. 비공개 바다 방문은 403, 보낸 편지 삭제 요청은 405였습니다. 연결을 끊고 보관을 누르면 실패 안내가 나오고 편지는 그대로 있으며, 연결 후 다시 누르면 보관됩니다. 근거는 표의 오른쪽 열에 적은 기록과 캡처입니다. 이 표에 없는 검사는 기기에서 해 보지 않은 것입니다.

## 12. AI로 수정한 사례

AI와 함께 고친 실제 사례입니다. 에뮬레이터에서 통합 확인을 하다가, 없는 아이디를 검색해도 아무 안내가 나오지 않는 것을 발견했습니다. 화면 명세에는 일치하는 사용자가 없다는 안내가 있어야 했습니다. AI에게 문서와 화면이 다른 이유를 코드에서 찾게 했고, 검색 결과가 비었을 때 보여 줄 내용이 코드에 빠져 있었습니다. 편지 쓰기 화면 파일에 안내 문구를 넣고 테스트에도 확인을 추가했습니다. 그 뒤 같은 에뮬레이터에서 같은 검색을 다시 해 안내가 나오는 것을 직접 확인했고 앱 테스트도 통과했습니다. 같은 과정에서 편지함 버튼이 안 눌리는 것처럼 보인 일도 있었는데, 그것은 앱 문제가 아니라 조작 도구가 대기 시간을 고려하지 않은 것으로 구분해 기록했습니다.

## 13. 완성 범위와 남은 문제

현재 상태를 구분한 표입니다. 에뮬레이터와 API, DB로 확인한 기능은 로그인, 발송, 보관, 버리기, 받은 편지함 삭제, 열람 후 이탈, 사용자별 설정입니다. 답장과 10개 초과 대기, 공유 바다, 바다 방문은 자동 테스트만 통과한 상태입니다. 남은 문제는 실제 휴대폰과 같은 LAN의 기기 두 대에서 확인하지 못한 것, 공유 바다 편지의 만료를 정하지 않은 것입니다. 아래 두 줄은 제공받은 자료와 직접 만든 부분의 구분입니다. 문서 양식과 작성 예시는 제공받았고, 주제와 규칙, 앱과 서버 코드, MySQL 구성, 시안은 직접 만들었습니다. 발표 뒤에 고치는 내용은 재검사 결과와 함께 이 장에 갱신합니다.

## 14. 실행 방법과 제출 정보

다른 사람이 실행할 때 필요한 정보입니다. 확인한 환경은 OpenJDK 27, Spring Boot 4.1.2, MySQL 8.0, Flutter 3.47.9, Android 에뮬레이터 Pixel 9입니다. MySQL을 켜고, 서버 폴더에서 gradlew bootRun을 실행한 뒤, 앱은 서버 주소를 API_BASE_URL로 주고 flutter run으로 실행합니다. DB 계정과 JWT 키는 환경 변수로 주며 값은 슬라이드와 문서에 넣지 않았습니다. 자세한 순서는 README 문서에 있습니다. 포트폴리오와 문서는 docs/portfolio/006_내포트폴리오 폴더에 있고, 지금 파일은 발표본입니다. 이 프로젝트는 아직 git 저장소가 아니어서 제출 위치에 소스와 문서가 실제로 들어갔는지는 제출할 때 따로 확인해야 합니다.
