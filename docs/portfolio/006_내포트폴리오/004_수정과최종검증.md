## 기본 기능 재확인
| 항목 | 실제 확인 결과 | 상태 |
|---|---|---|
| 서버와 앱 재실행 | 확인용 서버(8090)를 두 번 띄워 재시작 전후 네 테이블의 체크섬이 같았다(`docs/Data design example/db-verification.md`). 서버는 강제 종료했고 정상 종료 절차는 아니다. 앱은 강제 종료 후 다시 켜도 로그인이 유지됐다 | 통과 (서버 정상 종료는 미실시) |
| 로그인과 목록 조회 | `ichk01`로 로그인하니 내 바다에 유리병 4개가 보였다(`captures/login.png`, `sea.png`) | 통과 |
| 대표 기능의 정상 흐름 | 편지 보내기: 검색 → 입력 → 보내기 → 안내 → 보낸 편지함 한 줄, DB에 편지 26 한 행(`write.png`, `sent-toast.png`, `sent-box.png`). 보관·버리기도 화면과 DB 상태가 맞았다 | 통과 |
| 잘못된 입력과 권한 검사 | 빈 입력은 안내만 나오고 요청을 보내지 않았다. API로 401·403·404·405를 확인했고 DB 값은 그대로였다(`captures/api-03-permissions.txt`) | 통과 |
| 수정 후 데이터 유지 | 편지는 수정할 수 없는 자료라 "수정"이 없다. 대신 보관·버리기·보관함 삭제 뒤에도 보낸 사람의 보낸 편지함 4통이 그대로였다(`evidence/api-04-after-delete.txt`) | 대상 아님 (편지 수정 기능이 없음. 대체 확인은 통과) |
| PPTX·PDF 실제 열기 | PPTX는 PowerPoint로 열어 14장을 이미지로 내보내 확인했다. PDF는 PowerPoint에서 저장했고 14쪽인 것만 확인했으며 PDF 보기 프로그램으로 열어 보지는 않았다 | 통과 (PDF 열기는 미실시) |
| 실행 안내와 현재 코드 일치 | `gradlew bootRun --args='--server.port=8090'`과 `flutter build apk --debug --dart-define=API_BASE_URL=...`를 실제로 실행했다. `flutter run` 명령 자체는 실행하지 않고 APK를 빌드해 설치했다 | 통과 (`flutter run`은 미실시) |
| 토큰·비밀번호·서명 키 제외 | 이 폴더의 글·기록 파일에서 토큰·비밀번호 형태를 검색해 나오지 않았다. 캡처의 비밀번호는 가려진 점으로만 보인다. 서명 키는 쓰지 않았다(디버그 빌드) | 통과 |

상태는 실제 확인 후 통과·실패·미실시·대상 아님 중 하나로 기록한다. 대상 아님에는 이유를 적는다.

알려진 제한과 남은 문제:
- 실제 휴대폰과 같은 LAN의 기기 2대 동시 사용은 확인하지 않았다.
- 답장, 10개 초과 대기, 공유 바다, 바다 공개·방문은 자동 테스트로만 확인했다(서버 68개, 앱 151개 통과).
- 스켈레톤 화면은 에뮬레이터에서 응답이 빨라 눈으로 보지 못했다.
- 공유 바다 편지의 만료와 내가 띄운 편지를 다시 보는 화면은 정해지지 않았다.
- 개발 DB에 확인용 계정 `ichk01`·`ichk02`와 그 편지가 남아 있다.
