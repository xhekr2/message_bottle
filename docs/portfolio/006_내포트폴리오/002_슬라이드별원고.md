# 14장 포트폴리오 원고

아래 항목에 기존 문서의 필요한 부분과 실제 캡처 경로를 붙여 넣는다. 빈칸을 채우기 위해 사실을 만들지 않는다.

완성본: `포트폴리오_MessageBottle.pptx`, `포트폴리오_MessageBottle.pdf` (이 폴더). 캡처 경로는 이 폴더의 `captures/` 기준이다. 슬라이드에 들어간 글은 `build/deck.json`에 있다.

| 장 | 제목 | 붙여 넣을 자료 | 내 원고 또는 자료 경로 |
|---|---|---|---|
| 1 | 표지 | 앱 이름·작성자 | Message Bottle. "다른 사람의 바다로 유리병 편지를 보내고, 내 바다에 도착한 편지를 읽는 앱". 대표 화면 `sea.png`(내 바다, 실제 앱). 이름·소속은 `[이름] [학교·소속]`으로 남겨 두었으니 직접 입력한다. 발표본 2026-11-11 작성 / 최종본 미작성 |

| 7 | 시스템 구조 | 앱 → API → DB | Flutter(화면·입력·상태) → Spring Boot(API·JWT 인증·규칙 검증) → MySQL(사용자·편지·보관·설정). "앱은 서버 API만 호출하고, 편지 상태와 권한은 서버가 판단해 DB에 저장한다." 제공 예제는 H2, 이 프로젝트는 MySQL 8.0 |

## 넣지 않은 것

- 답장, 10개 초과 대기, 공유 바다, 바다 방문의 화면: 기기에서 찍은 캡처가 없어 화면으로 넣지 않고 4·13장에 "자동 테스트만"으로 적었다.
- 밤바다(`night-sea.png`)와 네트워크 끊김(`offline.png`) 캡처는 실제 화면이지만 14장 구성에 자리가 없어 넣지 않았다. 질문이 나오면 보여 줄 수 있다.
- 처리 속도, 사용자 수 같은 수치는 측정한 적이 없어 넣지 않았다.
